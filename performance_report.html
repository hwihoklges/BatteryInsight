다음 개선 순서

P1은 데이터가 늘어날 때 먼저 대응할 항목입니다. 아래 항목은 계획이며 아직 반영하지 않았습니다.

P1 변경된 실험만 갱신

watch는 입력이 같아도 정해진 주기마다 전체 묶음·분석·HTML을 다시 만든다. 304는 이 백그라운드 재계산을 없애지 않는다.

개선안 입력·등록표·설정·코드 revision별 의존성을 기록하고 변경된 채널과 관련 비교군만 무효화한다. 무변경이면 이전 분석과 게시 시각을 유지한다.

완료 조건 mtime·크기를 복원한 실제 내용 변경과 파일 손상을 계속 감지하고, 변경된 채널 추가·삭제·조건 변경의 결과가 전체 재계산과 정확히 같아야 한다.

P1 큰 실험 집합의 응답 크기

모든 실험 쌍과 지표 기여 상세를 생성·전송하므로 계산과 응답이 대략 O(N²·M)로 커진다. 200개 실험이면 19,900쌍이다.

개선안 쌍 목록에 서버 페이지 처리를 적용하고 선택한 연결의 기여지표만 지연 조회한다. 화면용 상위 K개 연결은 별도 표시 옵션으로 두고 전체 비교·내보내기는 유지한다.

완료 조건 필터·정렬·전체 다운로드 결과가 기존과 같고, 표시 제한이 과학적 비교 대상이나 그룹 평균을 바꾸지 않아야 한다.

P2 네이티브 raw 파서

대표 Cycle 85,809행 파싱 9.83초. 프로파일에서 필드 정규식 4,376,259회, datetime 변환 85,809회가 확인됐다.

개선안 51개 정수 필드를 엄격하게 배치 검증·변환하고, 사용하지 않는 datetime 문자열은 필요한 단계까지 생성을 늦춘다. ZIP schedule 검색도 채널 색인으로 공유한다.

완료 조건 기존 703,911행의 값·단위·행 순서·출처 전수 동등성, 정수 overflow·손상 행·step 경계 회귀를 통과한 뒤 적용한다.

P2 트랜잭션 복사

실제 개선 후 cProfile에서 rollback 준비에 약 1.88초, deepcopy에 약 0.96초가 들었다. 계측 오버헤드가 포함된다.

개선안 불변 분석 스냅샷과 변경 파일만 교체하는 트랜잭션으로 전체 메모리·HTML 백업을 줄인다.

완료 조건 저장 실패·보고서 실패·등록 실패를 주입해 파일과 화면 상태가 완전히 복구되는지 검증한다. 현재 rollback 보장은 유지한다.

P2 일반 CSV/Parquet 파이프라인 캐시

pipeline.code_fingerprint가 패키지 전체 Python 파일을 포함하므로 화면 전용 변경도 generic raw 처리 캐시를 무효화할 수 있다. 실제 native DB 경로와는 별개다.

개선안 수치 계산 의존 코드의 fingerprint와 전체 배포 코드 provenance를 분리한다. 의존 목록 누락을 막는 검사를 함께 둔다.

완료 조건 화면 변경은 raw 재처리를 유발하지 않고, 파서·단위·지표·진단 코드 변경은 반드시 관련 결과를 다시 계산해야 한다.

P3 압축·메모리

전체 새로고침의 Python 최고 메모리는 약 33.8 MiB로 전후 거의 같다. 압축 수준과 대규모 raw import 메모리는 이번 벤치마크 범위 밖이다.

개선안 원본과 동일한 전압 프로파일로 Zstd 수준별 크기·쓰기/읽기 시간을 비교한다. full_fields 외에는 중복 원시 필드 materialization을 줄이는 방안을 검증한다.

완료 조건 시간·전압·용량과 식별자·출처를 정밀도 손실 없이 보존해야 한다. 이번에는 저장 정책이나 기존 버전을 변경하지 않는다.

검증과 측정의 한계

  • 실제 데이터: 36채널, 관측값 2,944개, 전기화학 연결 116개. 분석·원곡선 전체 JSON을 값이나 메타데이터 제외 없이 비교했다.
  • 전체 새로고침은 각각 3회 중앙값, 합성 관계 분석은 각각 2회 평균이다. IO 카운터 실험은 파생 캐시가 없는 상태에서 각 1회 측정했다.
  • 같은 컴퓨터에서 Arrow/BLAS 작업자 1개로 실행했다. OS 파일 캐시를 비우지 않았으며 실행 부하에 따라 시간은 달라진다.
  • 메모리는 tracemalloc이 추적하는 Python 할당의 최고치이며 Arrow·브라우저·프로세스 전체 RSS를 뜻하지 않는다.
  • HTTP 캐시는 마지막 직렬화 응답 1개를 메모리에 추가 유지한다(이번 데이터 약 2.27 MB). 표의 새로고침 메모리 측정은 별도 HTTP 캐시 생성 이전이므로 이 비용을 포함하지 않는다.
  • 초기 직렬화 마이크로벤치마크는 전처리 범위가 달라 전후 속도 비교에서 제외했다. 304 수치는 HTTP 본문만이며 헤더는 포함하지 않는다.
  • 원본 파일과 실제 DB의 측정값은 변경하지 않았다. 원본 재수집·압축률 변경·데이터 삭제는 이번 개선에 포함하지 않는다.
