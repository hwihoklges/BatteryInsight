첫 장표를 주실 때

PPTX 또는 PDF 원본을 주시면 됩니다. 가능하다면 세트번호가 나오는 페이지, 샘플·채널 대응표, 날짜의 의미를 함께 알려 주세요. 한 번에 모든 정보를 채울 필요는 없습니다. 확인 가능한 내용부터 등록하고 나머지는 질문 목록으로 남깁니다.

아직 실제 장표는 등록하지 않았습니다. 샘플이나 날짜를 임의로 채운 실제 연결도 없습니다.

정리하면서 남길 항목

항목사용 시점먼저 기록하고 확인할 내용
장표와 근거 위치등록 필수원본 파일, 슬라이드/페이지/표의 위치, 해당 문구를 기록합니다. 그림만 있으면 판독 대기로 남깁니다.
실험명·목적확정 필수예: 구동압 비교, WIP 전후, RPT BOL. 제목이 넓은 주제이면 각 표·샘플의 실제 시험 목적을 별도로 확인합니다.
샘플 식별자·표기명확정 필수장표에 쓰인 이름과 내부 식별자를 구분합니다. 동일 샘플의 약어·별칭은 명시적으로 등록하며, 비슷한 이름을 자동으로 합치지 않습니다.
날짜와 그 의미raw 후보 연결 필수시험 시작일·종료일·제조일·보고일을 구분합니다. 연결 키에는 확인된 시험 시작일(test_start)만 사용합니다. 연도가 불명확한 6자리 날짜는 확인 전 확정하지 않습니다.
세트번호와 번호 사용 범위raw 후보 연결 필수세트번호는 문자열로 보관해 001과 1을 구분합니다. 프로젝트·장비 등 번호가 유일해지는 범위(namespace)를 함께 확인합니다.
시험 종류·RPT 시점raw 후보 연결 필수Cycle/RPT/DCIR 등의 종류, BOL/100cyc/WIP 전후 등 시점을 따로 기록합니다. RPT 내부 cycle 번호를 수명 cycle로 바꾸지 않습니다.
샘플과 채널의 대응표다중 후보 해소한 세트에 여러 샘플이 있으면 채널·셀 번호·원본 경로 등 대응 근거가 필요합니다. 날짜와 세트가 같아도 일대일 연결을 가정하지 않습니다.
물리 셀 ID·반복 시험 여부셀 평균·이력 연결같은 샘플명으로 만든 서로 다른 셀과 같은 셀의 후속 RPT를 구분합니다. 실제 동일 셀이라는 근거가 있을 때만 채웁니다.
설계·제조 배치설계 비교·셀 평균동일 설계와 제조 배치를 확인합니다. 샘플명이 같다는 이유만으로 같은 설계·배치로 지정하지 않습니다.
활물질·전극 구성·로딩확장 정보양극/음극 소재, 전해질·도전재·바인더, 조성 기준(전극 전체/활물질만), 로딩의 단면/양면과 mg/cm² 또는 mAh/cm² 단위를 기록합니다.
시험 조건비교 가능성 판단온도 °C, 압력 MPa, 충방전 C-rate, 전압 범위, formation 조건과 protocol을 구분합니다. 원본 프로토콜 식별자를 장표의 약칭으로 덮어쓰지 않습니다.
확정 여부·검토 이력확정 필수draft/confirmed 상태, 검토자·이유, 근거 ID, 버전을 남깁니다. 수정 이력은 보존하고, 기존 연결에 쓰인 기록이 바뀌면 재검토합니다.

한 장표를 추가할 때 진행할 일

  1. 파일 등록: 파일 SHA-256으로 중복을 확인하고 슬라이드/페이지별 텍스트·표를 근거 ID로 저장합니다. 장표 안의 지시문은 자료의 내용으로 취급하며 프로그램 명령으로 실행하지 않습니다.
  2. 초안 작성: 실험명·샘플·날짜·세트번호를 정리하고 각 기록에 근거 위치를 붙입니다. 그래프 범례·그림 속 표·겹친 텍스트는 원본을 확인한 뒤 사람이 정리합니다.
  3. 확인 목록: 누락, 서로 다른 장표의 상충 값, 별칭, 날짜 의미, 셀/채널 대응을 모아 질문합니다. 값이 없으면 빈 값으로 유지합니다.
  4. 등록 확정: 검토된 기록만 confirmed로 등록합니다. 기존 기록 수정은 새 revision으로 보존됩니다. 한 파일에 여러 실험·샘플이 있으면 개별 기록으로 나눕니다.
  5. raw 연결 검토: 확인된 날짜·번호 범위·세트·시험 종류로 후보를 만들고, 채널·샘플명·RPT 시점으로 좁힙니다. 후보가 하나여도 확인 이벤트가 있어야 연결합니다.
  6. 반영: 연결을 별도 overlay 파일에 저장하고 작업실이 이를 읽습니다. 원본 raw와 Parquet 수치는 그대로 두며, 표기명·설계·배치 등 검토된 메타데이터만 연결합니다.

데이터를 나누는 기준

문서 → 근거 → 실험/샘플 기록 → 연결 검토 → raw 시험 → 지표 순서로 출처를 추적합니다. 장표의 샘플 ID, 물리 셀 ID, 기존 raw 시험 ID는 서로 다른 키입니다.

실험·샘플 DB는 knowledge.sqlite3에, 대용량 원곡선과 지표는 기존 Parquet DB에 저장합니다. 문서 바이너리는 DB에 복제하지 않고 원본 경로·파일 해시·추출 근거를 보관하므로 장표 원본도 보관해 주세요.

샘플명은 셀 평균 기준이 아닙니다. 기존처럼 같은 설계·배치·조건·관측 시점 안에서 확인된 물리 셀별 동일 비중으로 평균을 계산합니다. 미확인 셀 ID를 이름으로 만들어 채우지 않습니다.

명령줄 사용 예

일반 사용 시에는 장표를 전달하면 이 절차에 따라 추가합니다. 아래 명령은 로컬 실행·재현용입니다. 경로는 실제 파일로 바꿉니다.

python -m pip install -e ".[documents]"
python -m battery_insight knowledge-init --out ../experiment_knowledge
python -m battery_insight knowledge-intake --registry ../experiment_knowledge/knowledge.sqlite3 --documents "실험장표.pptx" --out ../experiment_knowledge/review
python -m battery_insight knowledge-records --registry ../experiment_knowledge/knowledge.sqlite3 --records records.json --reviewer "검토자" --reason "슬라이드 표 및 채널 대응 확인"
python -m battery_insight knowledge-match --registry ../experiment_knowledge/knowledge.sqlite3 --database ../raw_database --raw-keys raw_keys.csv --out ../experiment_knowledge/matching
python -m battery_insight knowledge-link --registry ../experiment_knowledge/knowledge.sqlite3 --database ../raw_database --proposals ../experiment_knowledge/matching/proposals.json --decisions decisions.json --reviewer "검토자" --reason "시험 시작일·세트·채널 확인" --out ../experiment_knowledge/links.json
python -m battery_insight knowledge-export --registry ../experiment_knowledge/knowledge.sqlite3 --out ../experiment_knowledge/review

작업실 설정에 "knowledge_links": "연결 파일의 상대 또는 절대 경로"를 추가하면 확인된 연결을 읽습니다. 연결이 없어도 기존 작업실은 그대로 동작합니다. 장표 해석 수정, raw 내용 변경, 기존 등록표와 충돌하는 정보는 자동으로 덮어쓰지 않습니다.

알아둘 한계

  • PDF의 텍스트 순서가 표의 행/열 관계를 보장하지 않습니다. PPTX에서 그림으로 붙여 넣은 표, 스캔 PDF, 그래프 수치는 원본 확인이 필요합니다.
  • 현재 추출기는 문구와 위치를 수집합니다. 문구를 실험 사실로 판단하는 작업은 검토된 등록 기록 단계에서 수행합니다.
  • 공식 AIM 정의가 새로 확인되는 기능은 아닙니다. 장표의 결과 요약을 raw에서 계산한 지표처럼 저장하지 않습니다.
